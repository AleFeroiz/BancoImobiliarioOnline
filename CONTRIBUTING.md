# Como contribuir

Este projeto está começando. O fluxo abaixo é a proposta inicial para o repositório GitHub.

## Antes de começar

1. Confira `AGENTS.md` e os documentos em `docs/`.
2. Para uma mudança de produto ou regra, abra uma issue para registrar o resultado esperado e os critérios de aceite.
3. Para trabalho de preparação, documentação ou protótipo, uma issue pode ser dispensada quando o escopo já estiver combinado na conversa.

## Branches e commits

- Não faça trabalho diretamente em `main`.
- Use `feat/`, `fix/`, `docs/` ou `chore/` no começo do nome da branch; por exemplo, `docs/regras-iniciais`.
- Escreva commits curtos no formato Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:` ou `refactor:`.
- Mantenha cada pull request pequeno o bastante para revisão e inclua a issue relacionada quando houver uma.

## Pull requests

- Explique o problema e a solução em linguagem direta.
- Liste as mudanças visíveis e indique quais decisões de produto ou arquitetura foram afetadas.
- Registre como validou a mudança e inclua capturas de tela ou vídeo para mudanças visuais.
- Não marque uma validação como feita se ela não foi executada.
- Atualize a documentação afetada na mesma mudança.

## Ativos e referências

Use assets originais ou com licença compatível. Referências visuais ajudam a definir uma direção, mas não autorizam copiar arte, marca ou interface de terceiros.
